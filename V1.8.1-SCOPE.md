# V1.8.1 — surgical R2 redundant-therapy patch

## Why
V1.8 re-calibration exposed a gap: V18-1 (redundant SGLT2i) went **hard**, but via R1 dependency
(R2 returned valid=true). The R2 redundant-therapy check never fired — R1 happened to catch it because
that fixture is a shallow lookup. A *genuinely integrated* redundant-drug item would pass R1 and slip
through, because R2 wasn't independently detecting the duplication. V1.8.1 closes exactly that, nothing else.

## The one change (a17ClinicalPrompt STEP 1c, server.mjs only)
Rewrote STEP 1c into a mandatory explicit procedure R2 must execute before passing:
(i) LIST every current medication; (ii) map each to its DRUG CLASS (e.g. empagliflozin → SGLT2 inhibitor);
(iii) identify the keyed answer's drug class; (iv) if it MATCHES any current med's class → REDUNDANT →
valid=false, naming BOTH drugs and the shared class; (v) contraindication check; plus a mechanism-wording
sanity check. Explicit guard: "Do NOT pass an item just because the keyed drug's stated benefit is
individually true." integrated.mjs (gates/severity) UNCHANGED.

## New regression fixture — the decisive test (qa/v18-clinical-regressions.json → V18-4)
A genuinely cross-domain cardio-renal item (HFrEF + cardiorenal syndrome, haemoconcentration reasoning)
that SHOULD PASS R1, with a REDUNDANT keyed answer (patient already on empagliflozin; key = "add dapagliflozin").
Gate for this case: **R1 passes → R2 must INDEPENDENTLY return valid=false naming the empagliflozin/dapagliflozin
duplication → final hard.** This is what V18-1 could not prove.
