# Mega Q-bank — V1.5 Intelligence Map & Plan

_Read-only survey of what already exists on top of the question pool, the genuine gaps, and a phased plan. Everything below **reads** the frozen Smart-Drill engine; nothing modifies it._

Date: 2026-08-24 · Scope: `app.html` Q-bank + Smart-Drill layer (`:2848`–`:3800`), server pipeline already closed.

## 1. What already exists (do NOT rebuild)

The pool is richly tagged (`cognitive_level`, `skill`, `trap_type`, `subtopic`, `system`) and a mature analytics + adaptive layer already consumes it.

**Data model**
- `_qmeta[qh]` — per-question record: stem, options, answer, rationales, objective, tag, subtopic, skill, cognitive_level, system, src (`:3684`).
- `_attempts[]` — full attempt log (≤4000): qh, chosen, ok, ms, mode, confidence, ts (`:2951`, `:3685`).
- `_sessions[]`, `_events[]` — session summaries + telemetry.

**Aggregation — `qbAgg` (`:3172`)**
- Cumulative + **first-pass** accuracy, by system / tag / cognitive-level / skill / mode, fast-wrong counts, **mastery grid (topic × cognitive level)**, mistakes (last-attempt-wrong), session series.

**Frozen Smart-Drill brain — `smartStats` / `smartDiagnose` / `smartDrillPlan` (`:3394`–`:3585`)**
- Recency-weighted, **exam-horizon-aware** (`smartHalfLife` shortens as the exam nears, `:3385`).
- Confidence-weighted; **misconception detection** (confident-but-wrong).
- Evidence gates (`MIN_EV`), routing mix weak 50 / miss 20 / neglect 15 / maintain 15 (`SMART.MIX`), 2-day repeat cooldown, neglect tracking, human-readable "why".

**Student surfaces — Mega dashboard (`qbDashHtml :3261`)**
- First-pass KPI (labelled "predicts your real exam score"), "what to do next" recs (`qbRecs`), performance by system/topic/cognitive-level/skill each with one-tap **Drill**, **mastery-grid heatmap** (tap a cell → drill), **mastery states** (strong/developing/weak/critical, by skill/cog/topic/course), **confidence-calibration card**, session-trend spark, first-pass vs after-review.

**Adaptive actions**
- Smart Drill (personalised mix), drill-by-dimension (`smartDrillDim`), **concept retest** (a *different* question on the same concept — proves learning not memorising, `:3617`), adaptive difficulty along the cognitive ladder (`adaptStart :3790`).

**V1.6 — built but dormant (flag-gated OFF)**
- `GAP_LOOP` — gap → learn → practice → retest, A/B bucketed (`:3631`, flag `FEATURES.GAP_LOOP`).
- `POST_SESSION_FIX_QUEUE` — "3 things to fix" ranked by severity/confidence/recurrence, clustered by skill (`fixQueue :3104`, flag `FEATURES.POST_SESSION_FIX_QUEUE`).

**Telemetry** — `smartLog`, `smartValidation`, `pilotExport` (`:3459`, `:3524`).

## 2. The genuine gaps

1. **No cross-day spaced *schedule* for Q-bank items.** There's a 2-day cooldown and a recent-miss revisit inside Smart Drill, but no due-date ladder (like the recall deck's 1→3→7→14) that brings a missed/weak concept back **on a schedule** and shows a "due to re-test" count. The pool is a strong *on-demand* diagnostic + practice system, not yet a **durable memory loop**.
2. **The brain lives in Mega, not the daily entry point.** Home/Today drive the recall deck + streak; Smart Drill / fix-queue / readiness don't surface there. A student who follows the daily flow may never meet the Q-bank intelligence.
3. **No single exam-readiness signal vs the countdown.** First-pass is *called* a predictor and mastery states exist, but nothing folds first-pass × coverage × recency × calibration into one **"~X% ready for [subject] in N days"** number tied to the exam date.
4. **No coverage metric.** We can't tell "80% on the 10% of the bank I've tried" from "80% across the whole bank" — which readiness needs.
5. **V1.6 interventions unproven / unlit.** `GAP_LOOP` + `FIX_QUEUE` are built and OFF; there's no in-app validation readout to justify flipping them, and no staged rollout decision.

---

## 3. Phased plan (proposed)

Each phase is additive, reads the frozen engine, and ships behind nothing riskier than a flag.

**Phase 0 — Instrumentation (tiny, immediate).** Server: log `raw / removed / final` per build (the QB-12 signal). Client: a coverage counter (attempted ÷ pool size) per topic/subject. Groundwork for Phases 1–2; no user-visible behaviour change.

**Phase 1 — Q-bank spaced-retest schedule (the centerpiece gap).** Give each missed/weak concept a due-date ladder keyed by `qh`/concept (reuse the recall LADDER shape), surface **"N re-tests due"** on Home/Today, and feed due items into Smart Drill's miss slot. Turns the pool into durable memory — the single biggest behavioural lever, and the thing UWorld-style banks live on. New due-state store; frozen engine untouched.

**Phase 2 — Unified exam-readiness score.** Composite per subject/level = first-pass × coverage × recency × calibration, shown as "~X% ready · exam in N days" on Home and the dashboard. Reads `smartStats`; pure presentation of existing signals + Phase-0 coverage.

**Phase 3 — Bring the brain to the daily surface.** A Smart Drill / "fix these 3" CTA on Home/Today so the daily flow meets the intelligence, not just Mega explorers.

**Phase 4 — Validate + flip V1.6.** Use `smartValidation`/`pilotExport` to build an in-app validation readout, then stage `GAP_LOOP` + `FIX_QUEUE` on with evidence behind the decision.

---

## 4. Recommendation

Phases 1 → 2 → 3 are the V1.5 differentiation; Phase 4 is the V1.6 handoff. **Phase 1 (spaced-retest schedule) is the highest-leverage first build** because it (a) closes the only structural gap — durable memory — and (b) produces the "due" signal that Phases 2 and 3 surface. Phase 0 is an hour of groundwork that de-risks both.

## 5. Locked decisions (approved 2026-08-24)

Architectural sequence: **diagnostic brain (exists) → Q-bank memory state → due scheduler → daily surface → readiness (later)**. Readiness is NOT built right after Phase 1 — we watch the due-state behave first, so it's actionable, not a pretty number.

**1. Cadence — performance-aware 1 → 3 → 7 → 14 ladder.** Reuse the recall ladder's shape but drive it by performance, not blind progression: a scheduled item answered correctly-and-confident **advances** a step; past 14 it **graduates** (leaves the schedule); a **failure resets to +1 and escalates priority** (does not continue the ladder); a correct-but-unsure item holds its step (fragile) rather than advancing.

**2. Trigger — schedule by outcome × confidence, not just wrong answers:**

| State | Schedule? | Priority |
|---|---|---|
| Wrong + high confidence | Yes | 🔴 Very high (likely misconception → strongest intervention) |
| Wrong + low confidence | Yes | 🔴 High |
| Correct + low confidence (fragile) | Yes | 🟠 Medium |
| Correct + high confidence (secure) | No | — |

Unknown confidence (modes that don't prompt): wrong → schedule High; correct → do not schedule (can't call it fragile).

**3. Surfacing — fold into Today's commitment, no competing card.** The due count appears as a component inside the existing daily card, e.g. under Recall: "🧠 3 Q-bank concepts due for retest", tappable to start the retest — not a second standalone obligation. It does **not** gate the streak (streak stays new-learning + reviews).

**Concept/qh memory-state shape:**
```
qh · concept · attempt_count · last_result · confidence · misconception · streak · interval · due_at · last_seen · priority
```
(mastery is read live from the frozen `smartDiagnose`, not duplicated in the store.)

**Build order:** Phase 0 (instrumentation/coverage) → Phase 1 (memory state + scheduler + daily fold-in) → **watch** → then Phase 2 (readiness) only if the due-state behaves. QB-12 stays monitoring. QB-10/11 stay deferred.

## 6. Phase 0 + Phase 1 — BUILT (2026-08-24, pending push)

**Phase 0**
- `qbPoolSize(scope)` / `qbCoverage(scope)` → attempted ÷ pool size (groundwork for readiness; not surfaced prominently yet).
- Server: one parseable yield line per build — `[build-extra] qbank yield raw=N removed=M final=K` (QB-12 monitoring).

**Phase 1 — spaced-retest scheduler** (all in `app.html`, reads the frozen engine, never modifies it)
- Store `qbStore()._sched` keyed by question hash: `{qh,n,streak,interval,dueAt,lastOk,conf,miscon,prio,lastSeen,firstAt}`.
- `qbSchedApply(qh, ok, conf)` — the locked matrix: wrong+confident → prio 3 + misconception; wrong+unsure/unknown → prio 2; correct+unsure → fragile prio 1 (holds step); correct+confident/unknown → secure (never newly scheduled, advances an existing schedule). Performance-aware `1→3→7→14` ladder: correct-confident advances, past 14 graduates off, a miss resets to +1 and escalates. Ladder moves at most once per attempt-day (`_day` guard) so a late-arriving confidence value can't double-advance.
- Hooked at `qbNext` — fires exactly once per finalized question in tutor AND timed modes, after confidence is captured.
- `qbDueList` / `qbDueCount` — due today, priority desc then most-overdue; `qbStartDue` runs a cold tutor retest on the Mega page (answers flow back through the scheduler, so the loop is self-maintaining).
- Daily fold-in: a `🧠 N Q-bank concepts due for retest` component **inside** the Today's-commitment card (not a competing CTA; does not gate the streak), tap → `qbStartDue`.

**Verified:** server + app parse; 5 harnesses green; 18-case scheduler unit test against the locked matrix (all four states, ladder advance/graduate/reset-escalate, same-day double-advance guard, priority-ordered due retrieval). Frozen Smart-Drill engine untouched.

**Next: WATCH.** Before Phase 2 (readiness), observe the due-state behaving on real use — do items schedule, advance, and graduate sensibly; is the daily due-count reasonable rather than an ever-growing backlog. Only then build readiness on top of coverage.
