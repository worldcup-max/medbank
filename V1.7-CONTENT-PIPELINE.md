# V1.7 — Integrated Content Pipeline — CONTRACT (content-acquisition system, not a feature)

Precedes Integrated Mode + Case Mode. Turns the content gap into a measurable pipeline. **Frozen untouched:** Target layer, A6, A7, V1.6, and the core QBank. Each integrated item still resolves to ONE `primary_topic → target_id` (A6 owns retention); `integrated_topics[]` stays analytics-only.

## §0. Principle
The engineering is ahead of the content. We do NOT manufacture integration from the existing pool (the inventory probe proved that fails). We build a **second content layer** — Integrated Bank, later Case Bank — reusing the same questions/Targets for a different pedagogical purpose, fed by a controlled pipeline.

## §1. Educational hierarchy (the coherent progression this unlocks)
L1 QBank (can you answer?) → L2 Intervention (fix the specific miss) → L3 Blueprint (perform across a composition) → L4 Integrated (combine domains) → L5 Case (reason over an evolving patient). L4/L5 need this pipeline.

## §2. Integration taxonomy — LOCKED (a target, not an arbitrary tag)
- **Tier 1 Mechanistic** — two systems physiologically interact (cardio↔renal, endocrine↔renal, resp↔acid-base, hepatic↔pharmacology).
- **Tier 2 Diagnostic** — must combine findings across domains to reach the dx (neuro+endocrine, cardio+endocrine, infect+immunology).
- **Tier 3 Management** — treating one problem changes management of another (HF+renal, diabetes+CKD, anticoag+bleeding, pregnancy+CVD).
- **Tier 4 Competing priorities** — two legitimate objectives conflict (stabilise X but treatment threatens Y).
- **Tier 5 Longitudinal** — the patient's state changes over time → this becomes **Case Mode** (each stage still one Target).

## §3. THE DEPENDENCY TEST — LOCKED (the core gate; kills the `infect` noise)
An item is genuinely integrated ONLY if ALL hold:
1. Remove domain A → the answer changes (A required).
2. Remove domain B → the answer changes (B required).
3. Both domains are needed to solve it.
4. The secondary domain is a real **reasoning domain**, not merely a symptom / manifestation / risk factor / vocabulary of the primary disease.
*Test:* "febrile child with pneumonia" fails (remove 'infection' → still pneumonia; infection is the disease, not a second domain). "HF + worsening renal function after diuresis → adjust management" passes (both required; distinct domains).

## §4. Item schema (additive; second-layer)
```
id · question_id · primary_topic · target_id (primary, A6)
integrated_topics[] · integration_type(tier) · integration_family (e.g. cardio_renal)
integration_rationale · integration_dependency (why secondary domains are NECESSARY)
difficulty · source_question_ids[] (provenance) · review_status · reviewer · qa_score · created_at
review_status ∈ candidate | ai_reviewed | pending | approved | rejected | needs_edit
```

## §5. Pipeline — AI is candidate-finder, NEVER final judge
```
Existing QBank → AI candidate miner → AI ADVERSARIAL reviewer ("prove this is NOT integrated") → HUMAN approval → schema validation → Integrated Bank
```
- Miner proposes primary/integrated/tier/dependency + (optionally) a **transformation** of an existing question (retaining `source_question_ids` provenance) rather than free generation.
- Adversarial reviewer actively tries to destroy the claim (dependency test + "is the secondary a symptom?"). Two-model adversarial beats single-model "is this integrated?".
- **Human approves.** Nothing enters the bank on AI alone.

## §6. QA score — LOCKED (before approval)
| criterion | max |
|---|---|
| genuine multi-domain dependency | 3 |
| clinical coherence | 3 |
| educational value | 3 |
| answer discrimination | 3 |
| primary Target clarity | 2 |
| difficulty appropriate | 2 |
| no artificial complexity | 3 |
**Approve iff total ≥ 15/19 AND dependency criterion ≥ 3** (dependency is mandatory — a non-dependent item can never pass).

## §7. Content-readiness gate — LOCKED (do NOT expose Integrated Mode before this)
Minimum viable Integrated Bank: **≥100 approved · ≥8 integration families · ≥10 per major family · no single family > 30% · ≥3 approved per pair before that pair's analytics report** (prefer ≥5–10/pair). Strong bank: 250–500 across systems/dx/mgmt/mechanism/competing-priorities. Quantity follows quality — never "generate 500 to hit a number."

## §8. Incremental value before the gate
Ship curated single-family reasoning sets as families fill (e.g. "Cardio-Renal Reasoning — 12 questions") before a generic Integrated Mode exists. Seed with the strongest existing signal (**cardio+endocrine**), expand to high-value families (cardio-renal, endocrine-renal, resp-cardiac, neuro-endocrine, pregnancy-cardio, etc.) — each a content *target*, entered only after the dependency test.

## §9. Build order
1. **Deterministic core** (this turn): taxonomy + dependency gate + QA score + readiness gate as pure, tested functions.
2. `integrated_items` table (SQL) + review lifecycle.
3. AI candidate miner + adversarial reviewer (server; AI seams, mocked in tests — like A7).
4. **Review workbench** UI (per-candidate: original Q, proposed integration, dependency checklist, AI verdicts, human Approve/Reject/Edit) + provenance.
5. **Inventory dashboard** (approved/pending/rejected by family + pair; "ready for Integrated Mode? N/100").
6. At gate → unlock Integrated Mode over the dormant schema (little new engineering).
7. Case content pipeline → Case Mode (assemble from validated integrated items; each stage one Target).

**V1.8 branching untouched.** After this workstream, we return to the original QBank roadmap.

## §10. Next step
Deterministic core + tests delivered → STOP for approval → then SQL + AI miner + workbench.

## MINING RESULT + PIVOT — 2026-08-25
Mined 20 pediatrics questions → **0 integrable** (all clean rejections, no errors). Self-test control proved the miner discriminates correctly (genuine cardio-renal → `integrable:true`; single-domain seizure → `false`). **Conclusion: the pipeline/gate work; the pool (built around single Targets) genuinely lacks cross-domain integration — mining is the wrong tool here.**

**Pivot to TRANSFORMATION (contract §11):** `POST /admin/integrated/transform {question_id, family}` turns a validated single-Target question into a candidate integrated item (keeps `source_question_ids` provenance; canonical untouched), then runs the SAME adversarial gate + human approval. This *creates* integration deliberately instead of hunting for it. Built + tested (30/30 core). Hand-authored items can feed the same review queue.
