# V1.6 — Phase 1 Instrumentation — CONTRACT (observe-only; no UI, no generation)

Box: MEGA-QBANK-MASTER-ROADMAP → V1.6 → Phase 1. Builds on frozen A6 + A7. Reads (never modifies) frozen `smartDiagnose`.

## North-star rule (bold, non-negotiable)
**Phase 1 observes the existing learning system; it is NEVER part of the learning decision path.** If the `intervention_events` server is down, the QBank/scheduling/retention behave exactly as before Phase 1 existed.

## Locked decisions (Frank)
- **Durable server telemetry:** append-only `intervention_events` table + non-blocking POST. Keep local `smartLog` copy for debugging. The table *records* what happened; it does not *decide* anything.
- **Both diagnosis levels:** per-attempt `attempt_signal` (raw) AND `standing_diagnosis` (the `smartDiagnose` snapshot AS IT EXISTED at that moment — logged, never recomputed later).
- **Stable A/B bucket now:** `account_id → stable hash → A|B`, persisted, inactive, no UI/behavior. Assigning it in Phase 1 means Phase 2 can switch on the intervention without also changing cohort assignment.
- **Versions:** `diagnosis_version:"v1.5"`, `intervention_version:"v1.6-phase1"` for clean experimental lineage.
- **NONE of:** student-visible behavior, AI generation, V1.5 diagnosis change, A6 scheduler change, A7 change, blocking learning on telemetry.

## Identity
Keyed by **`target_id`** (from A6's `_qmeta` snapshot at attempt finalization), plus `qh`.

## Data chain
```
answer finalized → qbSchedApply() commits schedule (A6) → emit eligibility observation (fire-and-forget)
   event: { target_id, qh, ok, confidence, attempt_signal, standing_diagnosis, ab_bucket, versions }
   → local smartLog copy  +  async POST /telemetry/intervention  (never awaited, never throws into caller)
later → the next eligibility event for the SAME target_id IS its outcome (analysis joins consecutive events)
```

## attempt_signal mapping (per-attempt raw)
| outcome | confidence | attempt_signal |
|---|---|---|
| wrong | high (≥2) | `wrong_confident` (→ misconception candidate) |
| wrong | low/known | `wrong_unsure` |
| wrong | none | `wrong` (→ gap candidate) |
| correct | low (≤1) | `correct_unsure` (→ fragile candidate) |
| correct | high (≥2) | `correct_confident` (→ solid) |
| correct | none | `correct` |

## Server
Table `intervention_events` (append-only): event_id, account_id, created_at, target_id, qh, event_type, ok, confidence, attempt_signal, standing_diagnosis, ab_bucket, diagnosis_version, intervention_version. Endpoint `POST /telemetry/intervention` (auth user; insert; NEVER 500-loops the client — telemetry failure is non-fatal). Read: `GET /admin/intervention/stats` (cross-tab by attempt_signal × standing_diagnosis × bucket).

## Deterministic acceptance matrix (LLM-free, pure)
| # | Case | Expected |
|---|------|----------|
| 1 | `ivBucket(acct)` stability | same account → same bucket across calls |
| 2 | `ivBucket` domain | only 'A' or 'B'; ~50/50 over many accounts |
| 3 | `ivAttemptSignal` mapping | all 6 rows above map correctly |
| 4 | eligibility event shape | carries target_id, qh, ok, confidence, attempt_signal, standing_diagnosis, ab_bucket, both versions |
| 5 | **failure isolation** | a throwing POST / missing sink NEVER throws into the caller (ivEmit returns normally) |
| 6 | gated off | `ivOn()` false ⇒ ivEmit is a no-op (no local event, no POST) |
| 7 | no learning-path coupling | ivEmit has no return value the scheduler reads; qbSchedApply result is untouched whether ivEmit succeeds or throws |

## Exit
All matrix rows green (pure) → deploy behind `FEATURES.V16_TELEMETRY` (default off) → Frank runs the `intervention_events` migration + flips the flag → observe pilot data via `/admin/intervention/stats`. Phases 2–4 stay gated on the matched-intervention A/B outcome.
