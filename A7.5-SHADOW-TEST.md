## The 17-step chain

| # | Step | How the driver verifies it | Pass condition |
|---|------|----------------------------|----------------|
| 1 | Select a real test Target X with canonical questions | pick a `target_id` that has ≥2 canonical questions in the loaded corpus (prefer one with exactly the sibling count we can exhaust) | X chosen, canonical count ≥1 recorded |
| 2 | Confirm current canonical pool + retention state | `qbQuestionsForTarget(X, servedQhs)` count; `qbSched()['t:'+X]` snapshot | counts + record captured |
| 3 | Serve the LAST unused canonical | seed `servedQhs` so exactly 1 canonical remains, then `qbServeForRecord({key:'t:'+X, servedQhs})` | returns `{item}` (a canonical item), `pool.length===1` path |
| 4 | Canonical returned is unchanged | assert served item stem/options equal the actual last canonical question; `.a7` is falsy | identical + not an A7 item |
| 5 | Background `/retest/replenish` fires async | spy: confirm exactly one `POST /retest/replenish` was issued and **not awaited** before step-4 returned | 1 call, non-blocking |
| 6 | Generated candidates are valid | poll `GET /admin/retest/pool?target_id=X`; for each row assert `target_id===X`, `validation_state==='passed'`, `reason==null`, `reconciled_to===X`, `confidence≥0.85`, `matched_via∈{T1,T2,T3}` | all candidate rows conform |
| 7 | Candidates land ONLY in retest_pool | confirm no new rows in `topics.extras.qbank` for X (client corpus count unchanged) and rows exist in `retest_pool` | pool has rows; corpus unchanged |
| 8 | knowledge_targets + canonical QBank counts unchanged | compare `GET /admin/targets/stats` targetsCreated to `B1`; client corpus count to `B2` | both equal baseline |
| 9 | Pool reaches up to 3 candidates | after replenish settles, `GET /admin/retest/stats` / pool for X → `candidate` count ≤ 3 and, if generation succeeded, up to 3 | 1–3 candidates (or documented budget/gen stop) |
| 10 | Advance until X is due again | set the local `_sched['t:'+X].dueAt = dayNum()` (simulated time) | X due |
| 11 | A candidate retest served WITHOUT inline generation | `await qbEnsureA7()` then `qbServeForRecord` → served item is from `_a7Pool` (`a7:true`); confirm `/retest/serve` returned an existing candidate (no lazy call needed) | pool candidate served, no lazy gen |
| 12 | Its `qh` enters `servedQhs` | after the serve, assert the candidate `_qh` ∈ `sched['t:'+X].servedQhs` | qh recorded |
| 13 | Attempt uses the existing `t:X` retention path | `qbRetentionKey(servedItem)==='t:'+X`; run `qbSchedApply` on it and confirm the SAME record advanced | keyed t:X, one record |
| 14 | Same generated question cannot be served again | request another serve for X → the already-served candidate is not returned again (its qh is served) | no re-serve of the same qh |
| 15 | Emergency path: empty pool + lazy `want=1` | pick/clear a Target with empty pool (`POST /admin/retest/reset`), then `/retest/serve` → forces lazy `want=1` | serves a freshly-generated, validated candidate OR no_fresh |
| 16 | Generation failure → no_fresh, no retention advance, no cross-Target sub | simulate by pointing at a Target the model can't cleanly assess (or temporarily unreachable gen) → `/retest/serve` returns `{noFresh:true}`; assert no `_sched` advance and no other Target's item served | noFresh; retention untouched; no substitution |
| 17 | Final before/after invariants | re-run `B1`/`B2`; compare | knowledge_targets + canonical corpus counts equal baseline |

## Per-candidate evidence log (capture for EVERY generated candidate)

The driver dumps this table (fields already exposed by `GET /admin/retest/pool?target_id=X`):

| target_id | qh | generated_at | model | validation_state | reconciled_to | confidence | matched_via | reason | status | served_at |
|-----------|----|--------------|-------|------------------|---------------|-----------|-------------|--------|--------|-----------|
| … | … | … | … | passed/failed | X or other | 0.00 | T1/T2/T3 | null / structural / antidup / reconcile_* / match_other_target / below_floor | candidate/served/invalid | … |

This is the evidence that decides **freeze vs not** — not "the code passed," but: every served candidate was `passed / reconciled_to=X / confidence≥0.85`, and every reject carries an honest reason.

---

## Restoration (run last, always)

1. `POST /admin/retest/reset { target_id: X }` — delete all generated rows for X (and any emergency-path Target used in step 15/16).
2. Restore `qbStore()._sched = <B3 snapshot>` and `persist()`.
3. Clear client caches: `_a7Pool={}; _a7Inflight={};`.
4. Re-confirm `B1`/`B2` unchanged.
5. Set `DATA.flags.a7=false` for the test session (leave the flag as Frank decides for rollout).

**Freeze decision:** only if steps 1–17 pass AND every evidence row is clean (served ⇒ passed/reconciled=X/conf≥0.85; every reject has a valid reason). Then mark A7 frozen in `TARGET-LAYER-DECISION-LEDGER.md`.
