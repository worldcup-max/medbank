## §2. Evidence framework — LOCKED
Tiers by `seen` (attempts on that dimension, over ACCUMULATED history, not a single exam):
| Tier | `seen` | What it legitimately supports |
|---|---|---|
| **insufficient** | < 3 (`MIN_EV`) | **no claim.** Show "not enough data yet (n=…)". |
| **tentative** | 3–5 | a coarse read only ("early — roughly X%"); no strong narrative. |
| **measured** | 6–14 (`EV_MED`) | a precise descriptive % (e.g., "Management 58%, n=9"). Narrative allowed IF separated (§3). |
| **confident** | ≥ 15 (`EV_HIGH`) | confident descriptive %; narrative allowed. |

**Combination cells** (skill×cog, or `integrated_topics[]` pairs) need the SAME threshold *per cell*. On a typical 20-question exam a cell has ~1 attempt → **insufficient**. So combination claims stay "insufficient" until enough integrated data exists.

## §3. The narrative rule — LOCKED (descriptive, not diagnostic)
The cross-cutting insight ("your weakness isn't Medicine generally — you struggle with X") may fire **only** when:
1. the dimension is **measured** or **confident** (≥ `EV_MED`), AND
2. it is **clearly separated** from the student's own baseline — weakest dimension ≥ `SEP` percentage points below overall accuracy (`SEP` proposed 15).
Otherwise → **"not enough of a pattern yet — keep going."** Never phrase it as an ability judgment; always as measured performance with n. Never "your clinical reasoning is weak"; always "you scored X% on <dimension> (n=Y), below your Z% overall."

## §4. What Phase 3 does / does NOT do
- **Does:** consolidate the existing gated analytics into one Reasoning Profile view (overall · by-skill · by-cognitive, each with n + tier), apply the framework consistently, mark thin dimensions "insufficient" explicitly, hand off to Smart Drill.
- **Does NOT:** invent a new metric, claim ability, populate the combination axis from sparse data, or touch the frozen engine. Combination axis renders "insufficient — needs Integrated Mode."
