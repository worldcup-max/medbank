# V1.7 Phase 4 — Integrated Mode — CONTENT + ENGINEERING CONTRACT (READ→GAP done; NO implementation yet)

Box: MEGA-QBANK-MASTER-ROADMAP → V1.7 → Phase 4 (Integrated). Reuses runner/exposure/analytics. Frozen: V1.5/A6/A7/V1.6. **The `integrated_topics[]` metadata never becomes a scheduling identity — A6 keys the primary Target only.**

## §0. The job — and the risk
Make "Integrated" mean **a question that genuinely requires reasoning across 2+ clinical areas**, not a question that merely carries 2 tags. If we weaken that definition, Integrated becomes a cosmetic filter and the phase adds nothing.

## §1. Pool inspection — what the real data shows (2026-08-25)
Questions are not in the repo (`content.js` is a stub); they live in Supabase `topics.extras.qbank`, per account. Inspected the deployed pool via the app:
- **16 questions / 2 topics** visible (test account) — a small, per-account slice, not a global library.
- An auto-heuristic (stem mentions ≥2 distinct domain keywords + a synthesis skill) flagged **2 "candidates" (~13%)** — but reading them, **both are single coherent pictures** (puerperal sepsis: obstetric + infective in ONE clinical entity), **not genuine cross-domain integration**.
**Finding:** multi-keyword/multi-tag **over-counts**; genuine integration is **not reliably auto-detectable** and is **rare** in the visible pool. Inventory is currently **thin/unknown** → the content gate (§4) is the crux.

## §2. Definition — LOCKED (strict)
A question is **integrated** only if **solving it requires connecting ≥2 distinct clinical domains** — e.g., *diabetes + CKD + chest pain → drug choice constrained by renal function AND cardiac risk*. **NOT integrated:** a single coherent presentation that happens to touch multiple systems (puerperal sepsis), or a question with an incidental second tag. Test: *remove one domain — does the question still solve the same way? If yes, it's not integrated.*

## §3. Authoring `integrated_topics[]` — LOCKED
```
primary_topic     = the topic owning the question's Target / A6 identity (one target_id)
integrated_topics = the ADDITIONAL clinical domains genuinely required to solve it
```
- **Human-tagged (D1: reuse-first).** The auto-heuristic (§1) is only a **candidate screen for human review** — it surfaces questions to *check*, it does not classify. A human confirms genuine integration before `integrated_topics[]` is set.
- `integrated_topics[]` is **metadata only** — never a scheduling key, never an A6/A7 input (Phase 1 invariant, already proven).

**INVARIANT (LOCKED):** the pipeline is `pool → heuristic candidate scan → ADMIN REVIEW → human-confirmed integrated_topics[] → Integrated Mode`. It is **NEVER** `pool → keyword/AI detector → "Integrated"`. The heuristic never sets metadata and never labels a question "integrated"; only a human does.

**Inventory probe — BUILT (read-only):** `GET /admin/integrated/inventory` scans `topics.extras.qbank`, runs the domain heuristic + synthesis-skill filter, and returns totals, candidate rate, by-combination and by-skill breakdowns, and the three gates — explicitly framed as *"heuristic candidates, require human review; nothing written."* Zero student-behavior or metadata change.

## §4. THE CONTENT GATE — LOCKED (Integrated's "no silent substitution")
> **If the pool does not contain enough genuinely-integrated questions to produce a meaningful session, Integrated Mode must explicitly report insufficient inventory — it must NOT weaken the definition or backfill with ordinary multi-tag questions.**
Concretely: Integrated exposure selects **only** questions with a human-confirmed non-empty `integrated_topics[]`. If fewer than a minimum (proposed `INTEG_MIN` = enough to fill the requested count, or a floor like 5), it shows *"Not enough integrated questions yet"* and offers a normal session instead — never a disguised ordinary session labelled "Integrated".

## INVENTORY RESULT — 2026-08-25 (verdict: INSUFFICIENT, do not build)

Probe over 127 questions / 13 topics → **22 heuristic candidates (17.3%)**. But **6 of 9 combinations involve `infect`** (~17 of 22 candidates): in pediatrics, fever/infection is ubiquitous and a febrile child with pneumonia/meningitis is ONE infectious entity, not cross-domain reasoning (same false-positive as puerperal sepsis). Stripping infect-noise leaves **~3–6 plausibly-genuine** questions, concentrated in **cardio+endocrine (3)**.

**Gates:** G1 enough candidates? **FAIL** (~3–6 genuine — can't fill a session). G2 breadth? **FAIL** (~2–3 genuine combos). G3 per-combo MIN_EV≥3? **FAIL** (only cardio+endocrine plausibly genuine at 3).

**Decision:** Integrated Mode **NOT built** — per the content gate, it reports *insufficient integrated inventory*; do NOT weaken the definition. This is a **content** bottleneck (D1), not engineering. Options: (a) deliberately author/tag genuine integrated questions, or (b) **defer Integrated + Case** and treat V1.7 as shipped at Foundation + Blueprint + Reasoning Profile. Heuristic note: `infect`/`fever` over-counts as a "domain" (it's a symptom) — down-weight it for any future scan.
