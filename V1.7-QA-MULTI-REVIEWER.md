# V1.7 — Multi-Reviewer QA Pipeline (calibration-driven)

## Why
First human review of the machine-approved bank: **6/6 machine-pass, but only 1/6 production-clean.**
The single adversarial (dependency) reviewer validates *cross-domain dependency* well but does **not**
check clinical accuracy or single-best-answer defensibility. Exemplar failure: an SIADH item where a
2 mmol/L "correction" cannot cause osmotic demyelination, yet a pontine-MRI clue made the reviewer
rationalise the keyed answer. Dependency review alone is insufficient. Human review is non-negotiable.

## The pipeline
```
Generate/Transform → R1 Integration → R2 Clinical → R3 Single-best-answer → severity → HUMAN review → Approved
```
Three **separate** specialist reviewers (one model never polices integration + medicine + answer-uniqueness
at once). All are candidate-finders; the human is the only route to `approved`.

- **R1 — dependency** (`a17Adversarial`, unchanged + `quality` grade): does it genuinely require both domains?
- **R2 — clinical validity** (`a17ClinicalReview`, NEW): reconstruct the case from facts FIRST, reach a
  conclusion INDEPENDENTLY, then compare to the key. Never reason backwards from the keyed answer.
- **R3 — single-best-answer** (`a17SbaReview`, NEW): the DECISIVE output is a boolean — `defensible_alternative`
  (does a non-keyed option remain genuinely defensible AFTER correct reasoning?) — plus `distractor_answer_actually_correct`
  and `leakage`. The none/weak/strong grade is **metadata only** and never drives severity. (Live calibration proved
  the ordinal grade is not reliably controllable — the model can explain why a distractor is inferior yet still label
  it "weak"; so severity keys off the direct boolean, not the grade.)

## 7 PASS/FAIL criteria (in `qaVerdict`)
1. cross-domain dependency 2. clinical validity 3. single-best-answer 4. distractor validity
5. integration quality 6. stem sufficiency 7. no answer-leakage

## Severity model
| Severity | Trigger | Outcome |
|---|---|---|
| 🔴 hard | dependency fail · clinical invalid · reconstruction≠key · two equal answers · a distractor is actually correct · leakage forcing an unjustified key | auto-**reject** |
| 🟠 major | strong competing distractor · artificial integration · stem needs unstated assumption | to human, needs edit |
| 🟡 minor | adequate-but-shortcuttable integration · mildly defensible distractor | to human, tighten |
| 🟢 none | all clean | to human, ready to approve |

Only `hard` auto-rejects. Everything else goes to the **human queue** carrying its flags.
`applyHumanReview` will **not** let a human approve over a machine hard-fail.

## Content-quality layers (post-reviewer, advisory — added after the 100-run)
- **Answer-position rebalancer** (`rebalanceOptions`): deterministic seeded reorder of options + key/rationale remap. Fixed a 69%→~25% option-A skew; guarded by a distribution regression.
- **Option-prefix normalizer** (`normalizeOptions`): strips the generator's own positional letter labels so the UI's letter doesn't double ("A. A."). Positional-only, idempotent, never touches "E. coli".
- **Diversity layer** (`diversitySignal`): compares a candidate to the family corpus on wording AND reasoning STRUCTURE (family + intervention + demographic template). exact → auto-reject; high → suppress (bumped to major, human sees); moderate → warning. Independent of R1/R2/R3.
- **Source-aware budget** (`sourceBudget`, cap 3): counts distinct good candidates already produced from a source; once >= cap, transform skips it (no wasted LLM call) — smarter than text comparison because it reasons per starting point. Overridable with `force`.

## Scaling diagnosis (from the 100 + targeted 40)
Bottleneck is **source-pool breadth**, not the reviewers or the transformer. Dedicated sources took cardio_renal from 0%→85% R1 yield. Unique-reasoning yield is capped ~1 per unique source question — to get N distinct integrated items per family you need ~N diverse source questions (target 15–25/family). Isolation verified: `integrated_items` is admin-only; students cannot see any row.

## Two gates (kept separate)
- **Development / unlock gate** (`READINESS`, currently 20 / 8 families / ≥2 / ≤35%): lets us turn on a
  controlled pilot and learn. NOT deployed yet.
- **Production-strength gate** (future): substantially larger inventory, ≥3 per pair, usage evidence,
  no family dominance. This is the real quality bar; the dev gate is only for the pilot.

## Calibration regression (permanent)
`qa/v17-content-pipeline.mjs` encodes the 6-sample set with the reviewer signals a correct specialist
should emit, and asserts the severity model reproduces the human verdicts:
#1 minor · #2 major · **#3 hard** · #4 minor · #5 pass · #6 major.
**#3 is the adversarial exemplar** — if a future version passes it, the clinical-validity gate has regressed.

## Calibration philosophy — invariants, not exact labels
After the first live run, the regression tests SAFETY INVARIANTS (must hold), not exact ordinal severity:
- A clinical error (#3-type) is always HARD and never passes as valid.
- An inferior distractor (#5-type) never creates a hard/major flag, whatever its none/weak/strong metadata.
- An answer-preference where the reviewer prefers another VALID option (#6-type) is MAJOR, never a hard clinical fail.
- A clean item is none.
Calibration PREFERENCES (may land one level off without failing the gate): #2 → major, #5 → none, ambiguous → minor.
`qa/boundary-live.json` holds 8 blind, deliberately-different archetype questions run live to test that R2/R3
GENERALIZE rather than having learned the six. Scale to 30–50 only after invariants hold on the 6 AND the blind set.

## Live calibration protocol (after deploy)
The deterministic aggregation is unit-tested offline. What still needs a LIVE run is whether the LLM
specialists actually EMIT the right signals. After deploying `integrated.mjs` + `server.mjs`:
1. Re-run the same 6 sources through transform.
2. Compare each item's machine `qa.severity` to the human verdict above.
3. If the reviewers systematically disagree with human judgment, tune the reviewer PROMPTS (not the
   severity model) and re-run — before scaling acquisition.
Only once the reviewers agree with human judgment on the calibration set do we scale to 30–50 candidates.
