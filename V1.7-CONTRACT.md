## §0. The ONE job (scope guard)
> Turn the Mega QBank from a collection of Knowledge-Target assessments into a system that **deliberately trains and measures clinical reasoning.**

Every V1.7 feature must improve clinical *reasoning* (integrating knowledge, sequencing decisions, transferring across topics, and *measuring how a student reasons*). **If a proposed feature doesn't improve clinical reasoning, it is not V1.7.** Explicit non-goals: general "make the QBank smarter," new filters for their own sake, engine/diagnosis changes, branching (that's V1.8), AI content generation (content is tagged/authored first — Decision D1).

## §2. Dependencies on the frozen layers — and the ONE critical decision

**CRITICAL — integrated questions vs Target identity (A6 keys ONE `target_id`).** An integrated item spans `integrated_topics[]`, but A6 retention is keyed to a single Target. **Locked resolution (preserves A6/A7 frozen):**
- Every question — including integrated — has exactly **one `primary_topic` → one `target_id`** that owns its A6 retention. Integrated items schedule under their **primary** Target, exactly like today.
- `integrated_topics[]` are **measurement axes only** — used for combination analytics in the reasoning profile. They are **never** scheduling keys, never A6/A7 inputs. This keeps "one question = one retention Target" intact.

**Cases and A6:** a case = N question rows sharing `case_id`, each stage is its **own** question with its **own** `target_id`. So each stage is a normal Target assessment — A6/A7 are unaffected; the case adds a presentation layer (progressive reveal) + case-level scoring only.

**V1.6 interventions:** unchanged. They read the frozen skill-band diagnosis; V1.7 adds combination axes to the *profile*, not to the diagnosis. Diagnosis/routing stay frozen (spec §13).

**Result:** V1.7 sits cleanly on top — no new scheduler, no new retention key, no change to Target reconciliation. The frozen guarantees hold.

## §3. Proposed contract — locked principles
1. **Additive schema only.** New fields (`primary_topic`, `integrated_topics[]`, `case_id`, `case_stage`; reserve `branch_id`, `parent_question_id`). Existing single-topic questions behave exactly as today. No table changes (a case is N rows sharing `case_id`).
2. **One retention Target per question** (primary_topic→target_id). `integrated_topics[]` = analytics axis only.
3. **Reuse the runner + selector.** Integrated mode = a new exposure filter; Exam Blueprint = a smarter *item selector* in front of the existing runner; Case Mode = progressive reveal + case scoring over the existing runner.
4. **Measurement is evidence-gated.** The reasoning-profile narrative reuses `MIN_EV`/tiering — no confident "your weakness is X" off thin data (spec §9, §13).
5. **Frozen engine.** Reads `byCog`/`bySkill`/`smartDiagnose`; never modifies them. Hands off to Smart Drill via the existing path.
6. **Content-first.** Integrated/case items are tagged/authored before generation is considered (Decision D1). Don't let Integrated become "just a tag" — the integration-axis analytics are the value (spec §13).

## §4. Proposed build phases (map of spec §11 — each gated, shippable, tested before the next)
| Phase | Deliverable | Reuses | Gate |
|---|---|---|---|
| **1 · Foundation** | additive schema (`primary_topic`, `target_id`, `integrated_topics[]`, `case_id`, `case_stage`; reserve `branch_id`/`parent_question_id`); backward-compatible; **no A6/A7 change** | question object | new metadata coexists with A6/A7 with ZERO scheduling change; single-topic unaffected; `integrated_topics[]` never a scheduling key |
| **2 · Exam Blueprint** | build-my-exam (skill mix + cognitive mix, shortfall report, optional whole-exam timer; **no saved blueprints**) | runner + selector | blueprint honored or shortfall reported; content-free |
| **3 · Reasoning Profile** | evidence-gated, **descriptive** (not pseudo-diagnostic); no narrative until enough data; reasoning-performance dimensions | frozen V1.5 (`byCog`/`bySkill`) | breakdown + gated narrative; Smart Drill handoff; content-free |
| **4 · Integrated Mode** | tag existing integrating questions first; integration-axis analytics; **no generator; no scheduling change** | exposure switch | integrated-only selection; integration axis recorded |
| **5 · Case Mode** | assembled existing-question cases + small clinician showcase set; linear runner; **each stage an independent Target** | session runner | progressive reveal; per-stage + case scoring; tutor/test |

**Branching remains V1.8** (`branch_id`/`parent_question_id` stay reserved). Order (D5) is content-free first (Blueprint, Profile) → content-gated (Integrated, Case).

## §5. Decisions — LOCKED (Frank, 2026-08-25)
- **D1 — Integrated sourcing:** ✅ **A — reuse-first.** Tag existing questions that genuinely integrate ≥2 areas; hand-author a small number if needed. **Generator deferred.**
- **D2 — Timing:** ✅ **Whole-exam clock, optional** (untimed default; auto-submit at 0). Reuses the existing session timer. Per-question deferred.
- **D3 — Saved blueprints:** ✅ **Defer.** One-off Blueprint sessions first; persistence is convenience, not core reasoning value.
- **D4 — Case authoring:** ✅ **C + A hybrid.** Assemble coherent cases from existing questions + a small clinician-authored showcase set. **No case generator in V1.7.**
- **D5 — Build order:** ✅ **Foundation → Blueprint → Reasoning Profile → Integrated → Case.** Ship content-independent value first; don't let content block engineering.

## §6. Explicitly NOT in V1.7
Branching cases / decisions that change revealed info (`branch_id`/`parent_question_id` stay reserved → V1.8). AI generation of integrated/case content before tagging is proven. Any change to V1.5 diagnosis, A6 scheduling, A7 supply, or the frozen V1.6 contracts. General "smarter QBank" features that don't measurably improve clinical reasoning.
