## The locked loop (Frank)
```
WRONG + UNSURE → V1.5 = GAP → V1.6 Phase 2:
   LEARN (short explanation + the relevant note via q.src)
   → PRACTICE (one immediate active-application question, drawn from the Target's A6 siblings)
   → DONE
Then A6 (untouched) owns the retention retest:
   the original miss already scheduled the Target → A6 decides due date / interval / sibling → A7 if canonical exhausted
   → later outcome feeds V1.5 diagnosis → V1.6 learns whether it worked (via Phase-1 telemetry on the SAME target_id)
```

## Non-negotiable rules
- **Practice ≠ Retest.** Practice answers "did you learn it right now?" — a correct practice does **NOT** mean the gap is fixed. Only A6's later Target assessment ("did it retain?") does.
- **V1.6 NEVER touches retention.** Phase 2 must not call `qbSchedApply`, create, advance, or reschedule any `_sched` record. It may only *flag* the Target as needing remediation. A6 is the sole authority for due date, interval, sibling selection, exhaustion, and A7 fallback.
- **No second question-selection system.** Practice questions come from the Target's siblings via A6's `qbQuestionsForTarget(target_id, served)` — not a parallel `smartPool` tag+skill filter.
- **Identity = `target_id`** (not `skill|tag|objective`).
- Reuse-first, **no AI generation** in Phase 2 (A7 supplies retention questions only, and only via A6).

## Three measurement signals (why this is stronger)
1. **Initial failure:** Target X → gap.
2. **Immediate practice:** did they learn it now? (in-overlay, tagged `gap_practice`).
3. **A6 retention retest:** did it retain later? (A6/A7, spaced) — the truth signal, linked to (1)/(2) by `target_id` in the Phase-1 telemetry stream.

## Masking — RESOLVED (2026-08-25, Frank)
`gap_practice` is **intervention telemetry, NOT a V1.5 diagnostic attempt.** It is kept **out of `_attempts`** (the frozen `smartStats`/`smartDiagnose` input) so a correct immediate practice can never flip the standing diagnosis to `solid` and mask the gap before A6's retention retest. The frozen engine is **not modified** — we simply don't feed it. `gap_practice` is logged separately (`_gapPractice`) and durably (`POST /telemetry/intervention` with `event_type='gap_practice'`, `target_id`, `result`) so we can later analyze *"of gap-diagnosed students, how many succeeded immediately vs retained at the later A6 assessment."* Practice = acquisition; A6 retention = retention; they are measured separately.
